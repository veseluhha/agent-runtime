# Среда исполнения агента

Клиент-серверная среда для запуска агентских задач в изолированных Docker-контейнерах. Клиент отправляет задачу по HTTP. Харнес запрашивает следующее действие у прокси и через менеджер выполняет команду в контейнере. После запуска чекер проверяет файлы в рабочей папке, а клиент сохраняет результат и трассу в JSONL

В проекте реализованы пять базовых агентских функций из [курса Agentic LLM Systems](https://github.com/deeppavlov/agentic-course-itmo/blob/main/projects/A-agent-runtime.md): чтение, поиск, создание и правка файлов, вызов инструмента. Команды выбирает модель через Chat Completions API. Каждая задача получает временную папку `/work` со своей фикстурой и выполняется без доступа к сети

## Запуск

Нужны Docker с Linux-контейнерами, Docker Compose с поддержкой `--wait`, Python 3.9+, Make и OpenSSL

Сначала `make .env`, затем в локальном `.env` задайте параметры подключения

```dotenv
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=deepseek/deepseek-v4.1-flash-1017
LLM_API_KEY=<your-api-key>
```

Ключ остается в `.env`, который исключен из Git, и передается только model-proxy

```sh
make demo
```

Команда собирает сервисы и запускает все пять задач через gateway и модель. Без настроенного API запуск возвращает ошибку configuration. В терминале видны ID модели, ответы и вердикты чекеров. Клиент сохраняет сводку в `results/baf/live`, gateway записывает запросы и ответы API каждой задачи в `results/baf/record/<RUN>`

На работающем сервере `make baf-smoke` повторяет прогон с обращениями к API. `make test-ci` выполняет проверки клиента, протокола, харнеса и изоляции без внешнего API. Для остановки сервера -- `make down`

## Запись и replay с моделью

Для Б1.1–Б5.1 доступен общий прогон через Chat Completions с инструментом `run_command`. Он использует ту же модель и тот же цикл, что gateway, но сохраняет все пять задач в одном каталоге записи. В `LLM_BASE_URL` указывается базовый адрес API без окончания `/chat/completions`, в `LLM_MODEL` -- точный ID модели, в `LLM_API_KEY` -- ключ. Старые переменные `DEEPSEEK_*` поддерживаются, если ни одна переменная `LLM_*` не задана -- настройки разных провайдеров не смешиваются

Прогоны выполнены с [DeepSeek V4.1 Flash 1017](https://openrouter.ai/deepseek/deepseek-v4.1-flash-1017) через OpenRouter

```sh
make baf-record
```

В `results/baf/record/<RUN>/` сохраняются манифест с ID модели и хешами задач, JSONL с запросами и ответами API для каждой задачи и `results.jsonl` с исходами, временем и токенами. Каждый полученный ответ записывается до выполнения предложенных команд. У каждой задачи собственный таймаут из `task.yaml`, ошибки попадают в результаты. Команда печатает ID прогона и готовую команду повтора

```sh
make baf-replay RUN=<run-id>
```

Replay выполняет команды в новых контейнерах, сверяет контекст и вывод инструментов с записью и повторяет проверку файлов. Для повтора с подготовленными образами достаточно Docker и каталога записи. Ключ и доступ к API не требуются. Результаты повтора сохраняются отдельно в `results/baf/replay/<RUN>/`

## Результаты

6 ноября 2026 года проверила пять простых задач с DeepSeek V4.1 Flash 1017 -- 5/5 в режиме record и 5/5 через `make demo`. Запросы, ответы API, токены и вердикты сохранены в [результатах](docs/report.md)

Строгий replay первого прогона дал 4/5 -- у Б1.1 изменились временные метки в выводе `ls -la`. Полный БАФ-бенчмарк и сравнение моделей пока не проводились
