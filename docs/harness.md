# Харнес v0

Gateway строит реестр простых задач через runtime/tasks.py по файлам baf/*/*/task.yaml. Для выбранного ID run_smoke в runtime/harness.py получает каталог фикстуры, сообщения пользователя, имя выходного файла и бюджет времени. Контекст модели состоит из сообщений задания и предыдущих вызовов инструмента с их выводом. Чекеры и скрытая схема остаются в gateway

Цикл допускает один инструмент -- выполнение argv через /v0/exec в сандбоксе. После каждого вызова харнес отправляет историю прокси и запрашивает следующее действие. Для агентской команды модель получает exit_code и объединенный вывод stdout и stderr. Это позволяет разобрать упавшие тесты или сборку и сделать следующий шаг. Ошибка подготовки фикстуры, сбой транспорта или сандбокса прерывают запуск. У цикла также есть done, дедлайн и лимит восьми шагов. Сессия освобождается в finally

После done харнес переносит итоговое дерево /work во временный каталог и вызывает check.py с путем к этому каталогу. Файлы передаются побайтово, поэтому чекер может заметить лишнее изменение в README или новый файл. Текущий перенос рассчитан на маленькие фикстуры с обычными файлами и каталогами, сериализованный снимок должен помещаться в лимит вывода exec 64 КиБ. Ссылки и специальные файлы не поддерживаются. Для ответа CLI отдельно берутся первые 1024 байта файла answer_file

Реестр и харнес не содержат списка Б1–Б5. Правила тестовой модели сосредоточены в runtime/proxy.py. Добавление новой задачи для этого режима требует подготовить ее манифест, фикстуру, чекер и сценарий модели. Токены в успешном scripted-прогоне равны нулю
