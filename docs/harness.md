# Харнес v0

Gateway строит реестр простых задач через runtime/tasks.py по файлам baf/*/*/task.yaml. Для выбранного ID run_task в runtime/harness.py получает каталог фикстуры, сообщения пользователя, имя выходного файла и бюджет времени. Контекст модели состоит из сообщений задания и предыдущих вызовов инструмента с их выводом. Чекеры и скрытая схема остаются в gateway

Цикл допускает один инструмент -- выполнение argv через /v0/exec в сандбоксе. После выполнения команд харнес передает историю функции выбора следующего действия. Для агентской команды модель получает exit_code и объединенный вывод stdout и stderr. Это позволяет разобрать упавшие тесты или сборку и сделать следующий шаг. Ошибка подготовки фикстуры, сбой транспорта или сандбокса прерывают запуск. У цикла также есть done, дедлайн и лимит восьми шагов. Сессия освобождается в finally

После done харнес переносит итоговое дерево /work во временный каталог и вызывает check.py с путем к этому каталогу. Файлы передаются побайтово, поэтому чекер может заметить лишнее изменение в README или новый файл. Текущий перенос рассчитан на маленькие фикстуры с обычными файлами и каталогами, сериализованный снимок должен помещаться в лимит вывода exec 64 КиБ. Ссылки и специальные файлы не поддерживаются. Для ответа CLI отдельно берутся первые 1024 байта файла answer_file

Модель получает текст задачи и описание run_command, выбирает argv и получает результаты исполнения. Без настроенной модели запуск возвращает ошибку configuration до создания сандбокса

В обычном запуске через gateway и в отдельном режиме записи runtime/completions.py формирует запрос Chat Completions и связывает выход каждой команды с tool_call_id. Сообщение модели вместе с полями reasoning_content, reasoning и reasoning_details, если они присутствуют, возвращается в контекст следующего запроса. Для OpenRouter сохранение этих полей описано в [документации](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens). Gateway вызывает тот же раннер в режиме record для выбранной задачи, CLI получает вердикт, ID модели, токены и путь к записи. Раннер доступен только во внутренней сети Compose. Внешний запрос и авторизацию выполняет отдельный model-proxy, который поднимается вместе с gateway

В режиме replay runtime/experiment.py читает те же ответы из JSONL. Перед каждым ответом проверяется совпадение запроса, после завершения -- исход задачи, вердикт и превью ответа. Манифест связывает запись с содержимым манифестов задач, фикстурами и чекерами. tokens_in и tokens_out при replay равны нулю, расход записи указан отдельно. Если провайдер не вернул статистику, неизвестное значение записывается как null
