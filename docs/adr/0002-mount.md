# 0002 Монтирование клиентской папки в /work

SSHFS в пассивном режиме выбран для прототипа на выделенном Linux-сервере, 4 ноября 2026

Клиент открывает SSH-сессию и подает на нее SFTP из локальной папки через `rclone serve sftp --stdio`. Сервер монтирует папку через `sshfs -o passive`. Отдельный TCP-порт для SFTP на клиенте и переадресация через `ssh -R` не требуются. Docker получает готовый bind mount на сервере, сандбокс работает под UID 65534 без сети, доступа к Docker-сокету и устройству FUSE. Инструменты эксперимента и условия запуска описаны в [пробе SSHFS](../../experiments/sshfs/README.md)

WebDAV с rclone также дает доступ к клиентским файлам, но потребовал бы отдельно проверять кеш и момент публикации записи. NFS поверх WireGuard требует настраивать экспорт и сетевой интерфейс клиента. В испытанной конфигурации SSHFS клиент инициирует соединение самостоятельно, а изменения в закрытом файле видны в обе стороны

Точка монтирования должна быть видна Docker-демону. Попытка передать SSHFS из отдельного контейнера Docker Desktop через том с адресом `/proc/<pid>/root/export` завершилась ошибкой `invalid argument` при bind. На Debian-ВМ mount в пространстве имен Linux-хоста удалось передать обычным bind. Gateway пока создает сандбоксы с tmpfs, тестовый запуск берет параметры изоляции из того же модуля менеджера

Потеря транспорта может выглядеть как конец файла. Запись в уже открытый файл может оставить частичное содержимое на клиенте. Для интеграции нужен сигнал о потере mount, который переводит сессию в состояние ошибки независимо от кода команды. Для замены существующего файла отдельно предстоит проверить запись во временный файл и переименование после успешного закрытия. В пробе использовалась изолированная тестовая папка в режиме rw. Защита .git и ссылок, режим ro и восстановление активной сессии требуют собственных проверок
