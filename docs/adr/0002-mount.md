# 0002 Монтирование клиентской папки в /work

SSHFS в пассивном режиме выбран для прототипа на выделенном Linux-сервере, 4 ноября 2026

Клиент открывает SSH-сессию и подает на нее SFTP из локальной папки через `rclone serve sftp --stdio`. Сервер монтирует папку через `sshfs -o passive`. Отдельный TCP-порт для SFTP на клиенте и переадресация через `ssh -R` не требуются. Docker получает готовый bind mount на сервере, сандбокс работает под UID 65534 без сети, доступа к Docker-сокету и устройству FUSE. Инструменты эксперимента и условия запуска описаны в [пробе SSHFS](../../experiments/sshfs/README.md)

WebDAV с rclone также дает доступ к клиентским файлам, но потребовал бы отдельно проверять кеш и момент публикации записи. NFS поверх WireGuard требует настраивать экспорт и сетевой интерфейс клиента. В испытанной конфигурации SSHFS клиент инициирует соединение самостоятельно, а изменения в закрытом файле видны в обе стороны

Точка монтирования должна быть видна Docker-демону. Попытка передать SSHFS из отдельного контейнера Docker Desktop через том с адресом `/proc/<pid>/root/export` завершилась ошибкой `invalid argument` при bind. На Debian-ВМ mount в пространстве имен Linux-хоста удалось передать обычным bind. В пробе от 4 ноября gateway создавал сандбоксы с tmpfs

Потеря транспорта может выглядеть как конец файла. Запись в уже открытый файл может оставить частичное содержимое на клиенте. Для интеграции нужен сигнал о потере mount, который переводит сессию в состояние ошибки независимо от кода команды. Для замены существующего файла отдельно предстоит проверить запись во временный файл и переименование после успешного закрытия. В пробе использовалась изолированная тестовая папка в режиме rw. Защита .git и ссылок, режим ro и восстановление активной сессии требуют собственных проверок


19 ноября монтирование подключено к CLI и gateway. Сессия получает случайный ID монтирования, из которого менеджер выводит путь на Docker-хосте. После bind менеджер проверяет тип ФС и читает каталог из контейнера. Проверка до сообщения и перед выдачей результата отличает потерю папки от пустого ответа инструмента. В режиме чтения запись запрещают и SFTP-сервер клиента, и Docker bind. Запуски БАФ по-прежнему используют чистую tmpfs с фикстурой

При закрытии клиент завершает SFTP, SSHFS освобождает mount, серверный процесс удаляет каталог. Закрытие сессии удаляет сандбокс, у него также есть предельное время жизни 180 секунд. При обрыве уже открытая запись может остаться частичной. Фильтр экспорта скрывает .git из списка файлов. Политика конфликтующих изменений и восстановление открытого диалога после перезапуска gateway остаются открытыми

Для режима записи выбран rclone 1.74.4 с `--vfs-cache-mode writes --vfs-write-back 0s` и SSHFS с `sshfs_sync`. Временный кеш принадлежит одному процессу на клиенте и удаляется после его остановки. С прежним `off` дозапись `>>` оставила старое содержимое, хотя оболочка вернула 0. Нулевой интервал write-back у этой версии rclone включает синхронную публикацию при закрытии файла. Эти настройки допускают запись по смещению, ценой места на клиентском диске. Переименование подготовленной копии может перезаписать правку, сделанную другим редактором между чтением и заменой
