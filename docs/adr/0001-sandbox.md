# 0001 Отдельный Docker-контейнер на запуск

Принято для локального прототипа, 4 ноября 2026

Менеджер создает временный контейнер через Docker CLI и сокет демона. Харнесу достаточно приватного HTTP-интерфейса. Контейнер можно удалить целиком, включая потомков команды, а изменения в tmpfs исчезают вместе с ним. Эта граница проверяется тестом таймаута

Менеджер с сокетом фактически управляет хостом. Поэтому доступ к нему есть только во внутренней сети Compose, а сокет, ключ модели и токен клиента в контейнер задачи не передаются. Сам менеджер остается доверенным компонентом. Запуск сервера на выделенной Linux-ВМ ограничит последствия компрометации этой ВМ. Для многопользовательского развертывания стоит отдельно проверить rootless Docker с cgroup v2, включая работу лимитов и монтирования

Один общий контейнер был бы дешевле по времени старта, но потребовал бы вручную разделять процессы и состояние разных пользователей. Вложенный Docker потребовал бы отдельного демона и проверки его привилегий. Длительность старта пока не измерялась серией повторов
