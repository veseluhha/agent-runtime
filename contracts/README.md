# HTTP v0

[Клиент и gateway](client.json) и [харнес и менеджер](sandbox.json) описаны в OpenAPI 3.1. Сейчас это синхронный срез. В нем есть один ответ на запрос, CLI получает трассу по окончании запуска. Поток событий, восстановление по курсору, отдельные ReadFile, WriteFile и collect входят в следующий этап

Для exec ненулевой exit_code означает завершение команды с ошибкой. timeout закрывает сессию, output_limit делает то же при превышении 64 КиБ. sandbox означает сбой Docker или отсутствие сандбокса. Сбой соединения клиент классифицирует как transport. После неоднозначного сетевого сбоя provision и exec автоматически не повторяются, поскольку первый запрос мог успеть выполниться. Для повторной очистки можно отправить release уже завершенной сессии

Клиент получает список простых задач авторизованным POST /v0/tasks с пустым JSON-объектом. Для каждого ID он вызывает POST /v0/smoke с task_id. Успешный HTTP-запрос возвращает результат чекера, включая pass=false при несовпадении ответа, трассу и превью выходного файла
